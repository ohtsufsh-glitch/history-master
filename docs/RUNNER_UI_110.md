# Issue #110 ランナーのiPad横画面対応（v1.7.35）

基点はPR #109マージ済みの最新main `cafc3bb`（v1.7.34）。作業ブランチは `fix/110-runner-ipad-layout`。PR作成前にもfetchし、基点が最新のままであることを確認した。

## 変更と原因

- 親ページのmainは幅920pxまでなので、iPad横でも実際のiframe幅は846px。旧CSSの左右配置は子の高さ500px以下だけが対象で、それより高いiPadではHUD・814×457.88pxのCanvas・操作・説明文が縦に積まれ、内容高787pxになっていた。
- 既存の低い横画面条件に、**子iframeの幅700px以上かつ高さ900px以下**を追加。Canvasを左、HUDと操作を右へ配置する。機種名・UAでは分岐しない。iPad縦とiPhone縦は縦積みを維持。
- HUDの行を内容高、操作を上端揃えとし、横配置の開始ボタンは2行分の高さを確保。保存通知の有無や「最後の保存から再開（無料）」への変化でCanvas・ボタンを動かさない。
- 親のstickyヘッダーが初回表示のCanvas上部・HUDを覆う問題も目視で確認した。ホームからの**新規遷移時だけ**ヘッダーの実高＋8pxを`scroll-margin-top`に設定して、既存の1回の位置調整に反映する。iframe読込、resize、復帰、履歴移動で位置調整を追加しない。ホームに戻るボタンのDOM・デザイン・位置、英字タイトルは変更していない。
- 低い横画面は16:9セルの表示高を可用高さで制限し、既存の`resizeCanvas`が表示サイズを縮める。文字拡大や極小画面では結果の必要高を優先し、文書のスクロールを許す。結果パネル内で情報を切り捨てない。
- `.runner-help`のHTMLと関連CSSを削除。正式版・無料デモ・ステージ試遊から対象文言が消える。説明用の空要素や余白は残さず、Canvasのaria-labelは維持。
- APP_VERSION、親のCSS/import/iframe URL、子のCSS/JS/importの配信識別子をv1.7.35へ統一。ゲーム物理、アニメーション、S01〜S06、スター1個10点、ゆにこ能力・所持条件、残機・無敵、30コイン/test無料、保存・課金API、DB/backup v10、snapshot v2は変更していない。`runner/game.js`の差分はimportの識別子だけ。

## 状態ごとの安定性

全8サイズで以下の10状態を検証した。ゲーム時刻はテスト内のbridge.advanceで進め、実時間の描画との二重進行を防止した。ゲームの実装や物理をテスト用に変更していない。アニメーション・実時間入力は既存の専用テストでも別途確認している。

代表1180×700では全状態でCanvasのy=43.08、ジャンプのy=103.95、開始系のy=177.95が一定。各要素の幅・高さも一定。親のスクロール位置も操作中は一定だった。

文字200%では1180×700の子document高595、844×390で485、極小390×300で1080。必要な文書スクロールを許可し、結果パネル自体には内部スクロールがなく、タイトル・得点・記録・解放・再挑戦へ到達できた。

親の選択欄にはiframeのHUD上からの通常wheel入力でスクロールでき、子scrollTopは0のまま。実resizeではブラウザのscroll anchoringが選択カードの見た目の位置を保つ（iframe高の変化分だけscrollYが変わり得る）。その後のresize/orientationchange/pageshow/focusのイベント・refreshでは巻き戻しもiframe再生成もない。

## Safari実機で確認する事項

Safari実機・WebKit・VoiceOverは未検証。Chromiumのタッチ/サイズ模擬を実機の合格扱いにしていない。

- iPad横の開始前からCanvas・ハート・得点・ジャンプ・開始が同時に見え、固定ヘッダーに覆われず指で操作できること。停止/再開/両結果/保存通知/再挑戦/無料再開でも内側をスクロールしないこと。
- iframeのHUD/余白上からの指スワイプで親のステージ・キャラクター選択欄へ自然に移動できること。Canvasとジャンプ上では既存のゲーム入力が優先されること。
- アドレスバー伸縮、縦横回転、バックグラウンド/履歴復帰、遅いiframe読込で、選択欄からゲームへ勝手に巻き戻らないこと。
- iPhone縦の12px間隔、低いiPhone横、Safe Area、文字拡大、VoiceOverの読み上げ順・状態通知・無料再開への到達性。通常文字で不要な内部スクロールが残る場合は実機確認完了とは扱わない。
