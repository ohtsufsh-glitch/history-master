# 歴史マスター v1.6.7：景品配置の継続保存と無料入れ替え

Issue #7の確定仕様に対応。PR #9を含むv1.6.6のmain（`53f6450`）を基点とする。
mainへのマージ・GitHub Pagesへの本番デプロイはこの作業に含めない。

## 変更ファイルと動作

- `index.html`：APP_VERSIONをv1.6.7へ更新。盤面ストア追加、初期化、プレイのスナップショット、獲得確定、空枠判定、無料入れ替え、表示、バックアップ検証、プロフィール別初期化を変更。
- `tests/arcade_board_test.py`：永続化・空枠・入れ替え・競合・失敗時の巻き戻し・DB移行・旧バックアップ・初期化の回帰テストを追加。
- 既存の`tests/plush_test.py`、`tests/ui_cleanup_test.py`、`tests/question_editor_test.py`：既存検証を維持し、版番号・盤面スナップショットに関する期待値と架空データを新仕様に合わせる。
- 本書：保存形式と互換性、検証結果、実機確認手順。

初回は20種類から等確率・重複可で7体を配置する。次のプレイでも残っている景品の種類・位置を保ち、獲得した枠だけを空にする。失敗・運搬途中の落下では元の盤面を保つ。空枠を狙うと必ず失敗し、隣の景品へ判定を移さない。

全枠が空なら開始ボタンを無効にし、課金も行わない。「景品がなくなったよ！『景品を入れ替える』で新しくしよう！」と案内する。無料の「🔄 景品を入れ替える」で全7枠を再抽選する。残る景品があれば確認を表示する。入れ替えはコイン・獲得済みコレクションを変えない。

通常100コイン、テスト無料・無制限、20種類のID・名称・画像、アームの往復・移動速度・成功率・途中落下率・キャッチ演出、学習ロジックは維持する。既知のiPhoneのアーム下降位置とIssue #4は対象外。

## 保存設計とトランザクション

DB名は`history-master-sample-v1`のまま。DB_VERSIONとBACKUP_VERSIONを6→7、ストア数を13→14とする。新ストア`arcadeBoards`の主キーは`profile`。

```js
{ profile: "student", slots: ["shiba", null, "shiba", "star", null, "seal", "cloud"] }
{ profile: "test", slots: [null, null, null, null, null, null, null] }
```

- 常に7枠で、景品IDまたは`null`を保存する。プロフィールごとに最大1レコード。レコード不在と全枠`null`を区別する。
- `arcadePlays.prizes`は開始時点のコピー。過去の3体・7体プレイと獲得済み景品は書き換えない。
- 開始時は盤面・未完了プレイ・残高を同じreadwriteトランザクションで読み、スナップショット・料金・新プレイを一括保存する。
- 結果を`resolving`として保存してから既存の演出を再生する。演出後に`arcadePlays`・`arcadePrizes`・`arcadeBoards`を同じトランザクションで確定する。
- 7体プレイの完了時は現在の盤面と開始時のスナップショットを照合する。勝った1枠だけを`null`にする。失敗・途中落下では盤面を書き換えない。
- 完了済みプレイは再確定しない。途中でエラーが起きると、完了状態・景品付与・空枠化がすべてロールバックされる。
- 入れ替えは画面上の処理フラグで連打を防ぎ、保存トランザクション内でも未完了プレイと確認時の盤面を再照合する。別タブからの開始・入れ替えとの競合も拒否する。
- プレイ中、演出中、中断の再開待ち、保存中は入れ替え不可。

## DB6→7のアップグレード

`onupgradeneeded`では`arcadeBoards`だけを追加する。既存13ストアを削除・再作成しない。その後、起動時にプロフィールごとに盤面の不在を確認し、盤面とプレイ履歴を含むトランザクション内で一度だけ作成する。

1. 最新の7体プレイがaiming/resolvingなら、その配置をコピーする。
2. 最新の7体プレイがfinishedなら、その配置をコピーし、獲得成功した枠だけ`null`にする。
3. 利用可能な7体プレイがなければ7体を抽選する。
4. 旧3体の中断プレイがあれば、盤面の初期作成を延期する。旧プレイを元の3枠で手動再開・完了した後、上の規則で7枠盤面を作る。旧3体の結果によって7枠の景品を消さない。

ストア追加と盤面作成の間で終了しても、次回起動時に未作成分だけ再試行する。全枠が空でもレコードがあれば再抽選しない。

## バックアップ・復元・初期化

- v7完全バックアップは14ストアを同じreadonlyトランザクションで取得し、空枠を含む盤面・プレイスナップショットも出力する。
- v1〜v6を明示的に受理し、従来の世代別正規化を維持する。v1〜v3のコイン移行は旧履歴を報酬済み扱いにし、存在しなかったコインを新しく加算しない。
- 旧バックアップの盤面候補は、検証済みの復元対象プレイだけから作る。プレビューでは端末のDBに書き込まない。候補はプレビュー内に保持し、復元の再検証で再抽選しない。
- 復元は14ストアを同じトランザクションで全置換する。古いバックアップでも復元前の盤面は残さず、学習用・テスト用が混ざるのを防ぐ。
- 不正ID、7枠以外、不正値、重複プロフィール、空枠をつかんだ結果、未完了の7体プレイと盤面の不一致、料金・獲得記録の矛盾を拒否する。旧3体は従来どおり景品の重複・空枠を許可しない。
- プロフィール別初期化は対応する盤面だけを消す。次に開くと新しく作る。他方の盤面は保持する。完全初期化は両方の盤面を消す。
- 初期化のチェック・確認・完全初期化の文字入力は維持し、景品配置も消えることを対象表示に追加する。

## iPhone／iPad Safari実機確認手順（未実施）

マージ・本番公開の前に、ブランチを配信した安全なテスト環境で確認する。通常のSafariを使い、日常利用のデータと分けた端末・環境で復元／初期化を試す。更新前にv1.6.6の完全バックアップv6を非公開の場所に保存し、古いアプリを開いたタブを閉じる。

1. iPhone縦・iPad横で、7体の配置とサブボタン、案内文、コレクションが画面に収まり、44px以上のボタンをタップできる。
2. 学習用を100コインで開始し、1回だけ減る。テスト用は無料。狙う操作・往復速度・運搬演出が従来どおりである。
3. 同種を含む盤面で1体を獲得し、その枠だけが空になる。続けて遊んでも他の種類・位置は変わらない。失敗・途中落下では元の枠に残る。
4. 空枠を狙っても隣の景品を獲得しない。全枠を空にすると所定のメッセージになり、開始できず、コインは減らない。
5. 残存景品があるときの入れ替えをキャンセル／承認する。承認時だけ7体が補充され、コイン・獲得済み景品は変わらない。全枠空なら確認なしで補充できる。
6. 残存景品と空枠がある状態でリロード、Safari終了→再起動、iPad再起動を行い、配置が同じである。学習用／テスト用を切り替え、互いの配置に影響しない。
7. プレイ・キャッチ演出の途中で閉じて開く。再開ボタンを押すまでアームが動かず、入れ替え不可。手動再開しても追加消費・二重獲得がない。
8. 公開可能な架空データの旧3体／7体中断バックアップを復元する。旧3体を元の配置で完了し、その後7枠で遊べる。
9. v7を書き出して「ファイル」に保存する。プレビューだけでは盤面が変わらず、明示復元後に空枠・両プロフィール・学習履歴・残高・景品履歴が戻る。旧v1〜v6も安全なデータで確認する。
10. 一方だけの初期化で他方の配置が残り、完全初期化で両方が消える。キャンセルや誤った確認文字では実行しない。

自動テストはSafari実機の描画・タッチ・バックグラウンド終了・ファイル保存、iOS再起動、容量不足やOSによるWebサイトデータ削除を検証するものではない。端末間自動同期・PWA・iPhoneアーム下降位置の修正も今回の対象外。

## ロールバック時の注意

DB7を一度開いた端末では、DB6を指定する旧アプリはIndexedDBのVersionErrorにより開けない。DB名を変えたりストアを消して対処しない。復旧はDB7を扱える修正版を優先する。

v7バックアップは旧アプリで読めず、空枠を含むプレイも旧検証では拒否される。アプリの版だけを戻すことでデータも戻るとは考えない。必要な場合は更新前のv6バックアップと安全な別環境を使用する。v1.6.7で増えた学習履歴や景品は更新前バックアップには含まれないため、現行v7バックアップも非公開に保管して復旧を判断する。
