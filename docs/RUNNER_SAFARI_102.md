# Issue #102 — Safariランナー安定化（PR提案）

基点: `f212283`（PR #101マージ済みmain、v1.7.30）。変更後: v1.7.31。
DB/backup v10、snapshot v2、画像素材・物理・料金・解放条件は変更しない。

## 原因と変更

1. **別キャラの仮描画**: 未読込の画像をオレンジの汎用キャラへ置換していた。しば犬は最後に描画成功した同じキャラのコマ、または既存しば犬静止画を使用。画像が一度も使えない場合は選択キャラの名前を描画する。別キャラの画像は流用しない。同一URLのアイコンsrcを再設定しない。ゲーム進行・保存は画像成功を条件にしない。
2. **保存遅延**: checkpointのたびに全runnerPlaysをgetAll。さらに保存待ちのadvanceが解決した時点で終了を調べるため、古いフレームも終了後のrefreshを呼び、全5ストア読込と集計・DOM更新が重複した。保存を同じreadwrite TX内のget(id)→検証→putへ変更。終了した瞬間のフレームだけが再集計し、refreshは進行中のPromiseを共有。集計TXをreadonlyにし、同じsummaryの二重計算を解消。保存済み終了セッションのpause/closeは再保存しない。復帰照合は保存キューを待ち、読込中に保存版が進んだ場合は読取をやり直す。
3. **スクロールの巻戻し**: iframe.onloadとresizeのscrollIntoView、および重複visibilitychange→reconcilePage→iframe再生成。自動scrollIntoViewを撤去。ランナー表示中のvisibility/pagehideでは画面コンテキストを無効化せず、復帰・BFCacheでは既存iframeのデータ照合を行う。通常の戻る/進むは引き続きルート復元。削除・秘密キャラ権限喪失・別タブ保存が実際にあれば既存の安全な再照合を行う。

原子的保存、楽観的競合検出、途中再開、保存失敗時の未確定表示、DB正本に基づく新記録・解放、30コイン/テスト0コイン購入は維持。

## 実測

ローカルChromium、一時ブラウザの独立IndexedDB、390×844。3回の区間別中央値（ms）。
`tests/runner_safari_benchmark.py --baseline --slow` と `--slow` を使用。
`--slow` はCDP CPU 4倍遅延。**実機iPhoneの値ではない**。同じホスト上の負荷やスケジューリングによるばらつきがある。

| 条件 | 版 | 終了判定→保存TX完了 | 保存完了→再集計完了 | 再集計→最初の確定DOM表示 | 全体 |
|---|---|---:|---:|---:|---:|
| 追加履歴なし | main | 339.1 | 78.6 | 10.1 | 448.3 |
| 同上 | 修正版 | 7.3 | 36.3 | 6.6 | 55.1 |
| 終了履歴5,000 + 報酬20,000 | main | 11,537.5 | 980.6 | 13.6 | 12,531.7 |
| 同上 | 修正版 | 6.6 | 670.2 | 45.3 | 721.6 |

各列の中央値を個別に取っており、合計列と区間の和は一致しない。多履歴の全体範囲はmain 9,242.5〜17,242.0ms、修正版647.6〜976.5ms。
保存待ちフレームを確実に重ねるため、描画の自動進行を止め、実bridge.advanceを10フレームずつまとめて駆動する負荷試験。通常速度の実プレイ時間とは区別する。終了判定は同期モデル遷移直後、保存はsaveRunnerState解決（TX.oncomplete）、再計算はrunnerLobbyData解決、表示は子のrefreshFormalRunnerによる確定DOM更新で測定。実際の画面へのpaint時間は含まない。

同一駆動の全体でgetAllは36→5回、終了後のrunnerLobbyDataは5→1回。checkpoint保存呼出は11回で変えず、読取を各IDの1件へ限定した。残る5ストアの全読込は正本からの結果/残高/権限の再確認1回分。永続キャッシュやDB索引の追加はしていない。

## PR #103 レビュー対応 — ホームからの初回表示

ホーム下部の起動ボタンから遷移する正式E2Eで、修正前は390×844で操作ボタン下端が905pxになり、844×390/820×1180でもCanvasが画面上方へ隠れることを再現した。

明示的な `navigate('runner')` の呼出元が表示中のホームだった場合だけ、pushState後の同期処理で画面を切り替え、iframeホストへ一度移動する。iframeホストには従来と同じ85dvh（横90dvh）の高さを最初から確保し、子はその高さを使用する。案内行にも高さを確保する。位置調整をDB待ち・iframe.onload・タイマー・フレームコールバックへ持ち越さないため、その後のユーザースクロールを巻き戻さない。

通常のrestoreRoute/refresh/resize/visible/BFCacheやpopstateはこの入口処理を通らない。history.scrollRestorationも変更しない。画像・保存コード、データ形式には変更なし。版は同じPR内のv1.7.31を維持。

追加検証: ホーム下部からタップ→Canvas/開始/ジャンプのviewport内可視性（390×844、844×390、820×1180）、カードまで下スクロール→resize/focus/visibility/BFCacheで位置とiframe維持、iframe読込保留中の手動スクロール→読込完了後の位置保持、実際の戻る/進むによるホーム/ランナーそれぞれの位置復元。後者2件と初回表示テストはRunner iframe layout CIにも追加。実機Safariの未実施範囲は上記と同じ。
