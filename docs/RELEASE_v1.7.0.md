# v1.7.0 新学習モード（レビュー用）

対応: [#33 苦手克服](https://github.com/ohtsufsh-glitch/history-master/issues/33)、[#34 ジャンル別](https://github.com/ohtsufsh-glitch/history-master/issues/34)。ユーザー提示の「新学習モード実装仕様書 v1.0」と追加指示に基づく。共通基盤として一体実装したため1つのPRでレビューする。mainへのマージ・Pagesデプロイは行わない。

## 変更内容

- 苦手克服は現在出題可能な全時代の問題のうち、`activeProgress()` が現在版に一致し `everWrong === true && mastered === false` の問題のみ。未タグの問題も対象。ホームの時代選択より上に入口・件数・0件の案内を追加。
- ジャンル別は既存5タグの全時代の問題を対象とし、未挑戦・学習中・習得済みを含む。既存のジャンル理解度の表示を残して各行に開始ボタンを追加。タグ未設定・削除・非表示を除外し、0件では無効化。
- `questionWeight()` を利用して最大10問を重複なく抽選し、開始時にID・改訂番号・順序を固定。出題時・回答確定時に最新状態を照合。削除・改訂・苦手対象外の未回答問題は補充せずスキップ。
- 既存の問題・選択肢・正誤・解説・コイン表示・指摘を共用。上部にモード・進捗・出題元の時代を表示。最終回答後は解説とセット結果を表示し、実回答数を分母に集計。もう1セットは明示操作で開始。
- 回答、2連続正解での習得、カード、コイン、セット進行を共通の `saveAnswer()` の同一トランザクションで確定。問題の更新と進捗の競合も照合し、失敗時は全書き込みをロールバック。
- カード判定も同一トランザクション内で最新の時代別対象・進捗・獲得済み状態を確認。50問以上・全問習得の条件と獲得済みカードを維持。
- プロフィール×苦手克服、プロフィール×各ジャンルの独立したセットを保持。未回答の選択、選択肢順、回答結果を再読み込み後も復元。やり直しは未完了なら確認し、回答履歴・習得・報酬は取り消さない。
- History APIの既存v1時代別ルートを維持し、新しいstudyルートにはプロフィール・モード・ジャンルだけを保持。履歴から新規セットを生成しない。bfcache・フォーカス復帰時に正本を再照合し、画面回転では初期化しない。

## 保存と互換性

| 項目 | 変更 |
|---|---|
| アプリ | v1.6.18 → v1.7.0 |
| DB名 | `history-master-sample-v1` を維持 |
| IndexedDB | v8 / 15ストア → v9 / 16ストア。`studySets` を追加するのみ |
| 完全バックアップ | v8 → v9。セットの選択・途中結果・完了状態を含む |
| 問題JSON | `schemaVersion: 1` のまま。項目追加・必須化なし |

`studySets` のキーは `student:weak` / `student:genre:culture` 等（`test` は別）。レコードにセットID、開始・更新日時、問題ID・改訂の配列、現在位置、question/result/complete、選択肢順・選択、実回答結果、直近のコイン表示情報を保存する。正解数は実回答結果から算出し、別の習得履歴やコイン残高は作らない。時代別 `sessions` は従来のまま。

v1〜v8の完全バックアップを読み込める。旧形式のプレビュー・復元確認で、新モードの途中状態が含まれず現在のセットが破棄されることを明示する。問題・進捗・回答履歴はバックアップから復元し、セットだけがないことを理由に削除しない。v1〜v7の指摘保持の既存ルールも維持。v9は全16ストアを同一トランザクションで置換する。プロフィール別初期化と完全初期化にも `studySets` を含める。

## Issue #32との関係

Issue本文の先行依存・最低報酬の受入条件は、今回の追加指示に従い本PRの対象外とする。**正解0枚の補完は未実装**であり、このPRで#32を完了扱いにしない。金額・請求済み判定・復習報酬を変更しない。

後から統合する際の確認箇所:

1. `saveAnswer()` 内の初正解／初習得／復習報酬の確定後、`session.coinAward` と `coinStages` の設定前が補完処理の共通挿入箇所。`sessionStore` は時代別なら `sessions`、新モードなら `studySets` になる。全モードで同じ処理を通す。競合解消時に関数全体を旧版で置き換えず、問題の有効性照合・セット進行・カード判定の同一トランザクションを維持する。
2. `reviewEvents` を使う場合は回答UUID単位の既存トランザクション・二重保存防止を維持する。新モードの最終回答は同時に `phase: complete` になるため、最終回答でも補完額を保存・再表示できること。
3. `showResult()` は通常の結果とセット最終回答の両方で使用する。補完報酬のラベルを共通表示に追加し、再読み込み後も額・種類を一致させる。
4. #32のv8維持という記述に合わせて、本PRのDB／バックアップv9を巻き戻さない。古いデータと `reviewEvents` の検証・バックアップ互換性を確認する。
5. `tests/study_modes_test.py` と既存のコイン／履歴テストで、再習得途中・過去の請求済み・難易度別・最終回答・保存失敗・複数タブを確認する。
