# v1.6.14 — 指摘から改善依頼JSONを作成（Issue #20 Phase 2）

## 目的
v1.6.13のPhase 1で保存・集約された報告を、問題作成チャットへ安全に渡し、既存の問題マスター一括更新ワークフローへつなぐ。

## 変更点
- 管理画面「問題を管理する > 問題の指摘・改善管理」に、未確認・確認中の一括出力と、選択した指摘のみの出力を追加。
- 専用 `history-master-improvement-request` 形式v1で、報告を問題IDごとに集約し、現在の問題文・選択肢・正解・解説・難易度・ジャンル・改訂番号、報告時スナップショット、版不一致、対応状況を出力。
- 修正適用可能な問題のみ `baseRevision/baseHash` を含める。内蔵サンプル・削除/非表示・現存しない問題は、更新できない理由を明記。
- 指摘一覧で版不一致の報告について、修正前後の問題と変更項目を比較でき、保護者が「修正確認待ち」に手動変更可能。
- 既存一括更新後に開いている指摘一覧を再取得。指摘は自動削除・対応済み変更しない。
- 出力対象は最大100問、整形後8MiB以下。多い場合は対象の指摘を選んで分割。
- 新規自動テストは `tests/improvement_request_test.py` を追加。

## 互換性・変更しない事項
- DB名と `DB_VERSION=8`、15ストア、`BACKUP_VERSION=8` を維持。DB移行なし。
- 問題JSONの `schemaVersion=1`、既存 `questionUpdateFormat/formatVersion`、`baseRevision/baseHash` の更新前照合を維持。
- 回答履歴、習得判定、コイン、カード、ぬいぐるみ、クレーン、プロフィール分離、Phase 1の指摘JSON交換・重複管理・状態変更を維持。
- 改善依頼JSONは新規問題取り込み用でも更新用でもない。外部への自動送信はしない。
- 実教材由来の問題・指摘データは公開リポジトリに登録しない。

- `tests/improvement_request_test.py`：架空データによる回帰テスト。
- `docs/IMPROVEMENT_REQUEST_FORMAT_v1.md`：専用JSON仕様と運用手順。

## PR #24 検証・修正

対象は既存ブランチ `feat/question-feedback-phase2`。最新main `bbdc116`（Phase 1 / v1.6.13）を含むことを確認。新しいリモートブランチ・PRは作成せず、mainへのマージ・Pagesへのデプロイも行わない。

- 8MiB判定で、ダウンロード関数が加える末尾改行1バイトが数えられていなかったため、実ファイルと同じ文字列で容量を検証するよう修正。8MiBちょうどは可、1バイト超過は拒否。
- 内蔵サンプルの「アプリ本体の修正が必要」という案内を、版不一致の有無にかかわらず指摘一覧にも表示。
- 指摘と問題の読み出しを1つのreadonlyトランザクションに統一。選択はボタンを押した時点で固定し、ハッシュ計算中に画面・プロフィールが変わった場合は古い出力を中止。
- 100問上限の案内を、実際に分割できる「選択した指摘から改善依頼JSON」の操作へ修正。未確認・確認中の一括出力は一覧フィルターの有無にかかわらずその2状態全体が対象。

初回225件では223件成功・2件失敗。1件は新規テストが `importedQuestions[0]` を報告対象と誤認して別問題と比較していたため、問題IDで対象を特定し、問題全体とハッシュの比較も追加した。もう1件は既存UIテストの期待版がv1.6.13のままだったためv1.6.14へ更新した。検証の削除・skip・assertの緩和は行わない。

追加の回帰テスト12件を加えたため、最終の検出数は **237件＝Phase 1までの211件＋PR追加済み14件＋今回12件**。全体再実行で見つかったPhase 1の分割ダウンロード試験の待機競合は、案内文だけでなく両ファイルのdownloadイベントを待つよう修正した。件数2・各ファイルの上限・合計5,001件・再取り込み可能というassertはすべて維持。

追加12件は、更新JSONの実保存・習得維持／リセット・旧履歴とカードとコインと指摘の保持、古いbaseHash/baseRevision・保存直前競合の拒否、UI更新後の比較、改訂番号だけの相違、内蔵サンプル案内、他タブの状態保護、容量境界、100問での複数報告保持、HTML注入と余計なデータの除外、カード10枚、生成中の遷移・選択固定を検証する。
