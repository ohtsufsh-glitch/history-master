# 歴史マスター v1.6.5：景品20種類対応

## 変更内容

作業開始時にGitHubから取得した `main`（`11b4074`）を基点とする。
同版のソースコメントには v1.6.2／v1.6.3 が残っていたため、今回のアプリ版コメントを v1.6.5 に更新した。

- `index.html`：既存5種類の後ろに指定の15種類を追加。抽選・画像パス・バックアップ検証は従来の景品定義参照を利用する。
- ホームの紹介文・獲得種類数・コレクションの分母・コンプリート判定は `PLUSH_IDS.length` から求める。
- コレクションは従来のiPad向け5列／小画面3列グリッド、未獲得画像の暗表示、重複獲得数、遅延読み込みを維持。画像の非同期デコードを指定する。
- `assets/plush/`：提供ZIPから追加15枚だけを無変換で配置。既存5枚は変更しない。
- `tests/plush_test.py`：公開可能な架空データと一時的なIndexedDBを使う回帰テスト。

追加画像：`rabbit.webp`、`chick.webp`、`seal.webp`、`penguin.webp`、`hamster.webp`、`capybara.webp`、`redpanda.webp`、`kitten.webp`、`puppy.webp`、`piglet.webp`、`jelly.webp`、`otter.webp`、`bird.webp`、`cloud.webp`、`star.webp`。

7体・等確率・重複可の抽選、アーム操作・速度・判定・途中落下・運搬アニメーション、学習ロジック、コイン料金、プロフィール分離、手動再開・二重消費防止・二重獲得防止の処理は変更しない。iPhoneでアームが届かないように見える既知の問題は今回の対象外。

## データ互換性と更新時の注意

- DB名 `history-master-sample-v1`、DBバージョン6、13ストアの構成・キー、完全バックアップ形式v6を維持。今回の更新によるデータ移行・初期化・既存記録の書換えはない。
- 旧3体配置と7体配置の保存データを引き続き読み込む。再開はユーザーの明示操作で行う。
- バックアップv3〜v6の互換分岐を維持。景品IDの検証は `PLUSH_TYPES` を参照するため、追加景品も同じv6形式で検証・復元できる。
- **追加景品IDを含むバックアップは、旧5種類のコードでは検証に失敗する。復元にはv1.6.5以降を使用する。** v6という形式番号が同じでも、古いアプリへの復元を保証しない。
- 更新前の完全バックアップは非公開の場所に保管する。実機で復元を試す際は、通常利用のデータと分けたテスト環境を使う。

## 自動検証

実行方法（Python・Playwright・Chromiumが必要。アプリの依存追加はない）：

```sh
PYTHONDONTWRITEBYTECODE=1 HISTORY_MASTER_BROWSER=/usr/bin/chromium python -m unittest discover -s tests -p '*_test.py' -v
```

テストはlocalhostと一時ブラウザだけを使用する。教材由来の問題、実際の家族の記録、公開サイトは使用しない。

検証結果：Chromiumで既存7件と景品関連9件、計16件が通過。景品関連8件の通過後、追加した更新保持テスト1件を修正・個別再実行して通過を確認した。

## iPad／iPhone Safari実機の確認手順（未実施）

マージ・本番公開の前に、作業ブランチを配信したテスト環境で確認する。通常のSafariを使用し、復元試験は日常利用のデータを入れていない環境で行う。

1. iPad横向きでホームに「全20種類」と獲得種類数が表示される。コレクションに既存5種類→追加15種類の順で20件が並び、最下段までスクロールできる。小さい文字・折返し・タップ操作を確認する。
2. コレクション全体をスクロールし、透過WebP20枚が表示される。未獲得は暗く、獲得済みはカラー、同種2体以上は `×2` などになる。描画中の引っ掛かりも確認する。
3. 安全なテストデータで19種類は未完了、20種類で「コンプリート！」になることを確認する。
4. 学習用のプレイ開始で100コインを一度だけ消費する。保護者テストでは残高0でも繰り返し遊べ、学習用のコイン・景品・履歴が変わらない。
5. アーム往復中に画面を離れ、戻るかSafariを開き直す。再開ボタンを押すまでアームが止まり、押した後も追加料金が発生しない。キャッチ後の中断も試し、景品が二重登録されない。
6. 旧3体／7体の中断プレイを含むテスト用バックアップを復元し、配置・再開を確認する。新景品を含むv6バックアップを「ファイル」へ保存し、選択→検査→明示復元後に獲得数・各履歴が一致する。
7. iPhone縦向きでも20件のグリッド・スクロール・画像表示・ボタン操作を確認する。アーム到達距離の修正は今回の合否対象に含めない。

自動テストの画面サイズ再現はSafari実機の描画・タッチ・バックグラウンド復帰・ファイル保存の確認を代替しない。`main`へのマージとGitHub Pages更新はこの作業では実施しない。
