# 歴史マスター v1.6.8：Safari履歴連携と学習データ・コイン残高の整合性保護

Issue #13に対応。基点は最新mainのv1.6.7（`f29b4f6`）。本変更は専用ブランチからのレビュー用で、mainへのマージ・GitHub Pagesへのデプロイは行わない。

## 変更概要

- ホーム・問題・管理・キャッチャーをHistory APIで連携。ブラウザの戻る・進むで画面とプロフィールを復元する。
- リロード、bfcache相当の`pageshow`、タブ表示復帰でIndexedDBを照合し、現在の問題・結果・選択肢順・残高・中断プレイを再表示する。
- 回答保存開始時のプロフィール・時代・問題・選択・選択肢順を固定。保存後は正本を読み直し、移動先や別タブが進めた問題に古い結果を描画しない。
- 残高は`coinEvents + reviewEvents - coinSpends`を同じreadonlyトランザクションで取得する。照合中は「確認中…」、読み取り失敗時は「確認できません」と表示する。
- キャッチャーは復帰後に手動再開。演出途中で離れると、保存済みの結果を再開ボタンで確認する。追加課金・再抽選・二重獲得を行わない。

## コイン減少疑いの調査

元のSafari報告の根本原因、および端末内の記録自体が減少したかは未確定。Safari実機・実利用者のデータを調査したとは扱わない。

確認した呼び出し関係：

- v1.6.7の`show()`は表示切替と残高更新、`renderHome()`は理解度等の非同期取得後に`show("home")`を呼ぶ。履歴APIと学習状態を照合する`pageshow`はない。
- `startEra()`は`sessions`を再開し、なければ`advance()`で抽選・保存、`renderQuestion()`で描画する。
- `grade()`→`saveAnswer()`は回答・セッション・進捗・カード・報酬を一括確定する。一方、従来の`grade()`は待機後のグローバルな選択肢順を使用し、保存後の描画に画面世代の確認がない。
- `getAvailableCoins()`は3ストアを別トランザクションで取得し、`refreshCoinDisplay()`は取得開始時のプロフィールと描画時の画面を照合していない。
- `openAdmin()`・`beginTestMode()`・`returnToStudentHome()`は画面とプロフィールを変更するが履歴情報を持たない。`openArcade()`は手動再開待ちにする。`pagehide`はアーム停止、`visibilitychange`の表示復帰は自動往復再開を呼んでいた。

架空データを使い、変更前v1.6.7と修正版で比較した事実：

| 操作・記録 | v1.6.7 | v1.6.8 |
|---|---|---|
| 初期の学習用残高 | 805枚 | 805枚 |
| 別タブでキャッチャーを1回購入した後の保存残高 | 705枚 | 705枚 |
| `pageshow(persisted=true)`後のホーム表示 | 805枚のまま | 705枚へ更新 |
| `coinEvents` / `reviewEvents` / `answers`全プロフィール合計件数 | 4 / 402 / 4のまま | 4 / 402 / 4のまま |
| `coinSpends`全プロフィール合計件数 | 0→1 | 0→1 |
| 遅延させたホーム描画の途中で管理画面を開き、その描画を完了 | ホームに戻ってしまう | 管理画面を維持 |

この比較では報酬・回答レコードの削除はなく、残高の100枚減少は明示的な購入1件と一致した。表示が保存残高に追随しない経路と、古い描画が移動先を上書きする経路を再現した。これを元の「Safariでコインが減ったように見えた」報告の原因と断定しない。3ストアの別取得に起因する残高の食い違い自体も、この比較では再現していない。

保存中の離脱・トランザクション中断・プロフィール切替・同時回答は追加テストで検証する。Safari固有のbfcacheの保持・破棄、OSによる終了、容量不足、実データ減少の有無は実機確認に残る。

## 画面遷移と保存の設計

`navigate()` / `navigateHome()`がユーザー起点の遷移、`restoreRoute()` / `restoreQuiz()`が保存済み状態の復元、`show()` / `renderHome()`等が描画を担当する。将来のIssue #14のホームボタンも`navigateHome()`を再利用できる。

履歴stateは`{app:"history-master", version:1, screen, profile, era}`だけ。問題ID・選択肢・採点・報酬を履歴に複製しない。初期化は`replaceState`、異なる画面へのユーザー操作は`pushState`、`popstate`とページ復帰は履歴追加なし。同じ画面の再描画でも履歴を増やさない。URLは変更しない。

ゲーム内ホームはアプリ内のホームエントリを追加する。直前の履歴を推定して`history.back()`を呼ばないため、外部ページや履歴不足でも意図せず外へ出ない。このため、そのホームからブラウザの戻るを押すと直前の問題・キャッチャー等に戻る。ブラウザの戻る・進むだけで履歴は増えず、初期ホームからの戻るは通常の外部履歴に従う。

- 有効なセッションがあれば同じ問題・選択肢順・phase・保存済み報酬を復元する。復元時に`grade()` / `saveAnswer()`を呼ばない。
- 未確定の選択はタブ内メモリで保持し、保存セッションが同一の場合だけ再利用する。リロードやプロセス終了を越えた未確定選択の保持は保証しない。
- セッションが削除・更新されていれば、履歴復帰だけで新規抽選せずホームへフォールバックする。ユーザーの時代選択と「次の問題」だけが必要な新規抽選を行う。
- `sessions`と対応する`progress`を同じreadonlyトランザクションで読み、表示した状態を保持する。回答のwriteトランザクション内で両方を再照合し、別タブにより変更されていれば中断する。新問保存も比較後に書き込み、他タブのセッションを上書きしない。ストア・レコード形式は追加しない。
- 初期化・バックアップ復元の書き込みが確定した後は、共通処理で未確定選択・表示中セッション・進捗の参照・選択肢順をクリアし、古い非同期描画を無効にする。管理画面はそのまま、プロフィールと現在の履歴stateをstudentへ同期する。履歴は`replaceState`で置換し、過去のtestエントリは本来のプロフィールで復元できるよう維持する。キャンセルや書き込み失敗ではこのクリアを実行しない。
- 同一タブの回答保存中に復帰した場合、保存完了または失敗を待って正本を取得する。保存失敗なら未回答、別タブが回答済みならその保存結果を表示する。
- 画面世代・プロフィール・描画要求番号で古い非同期処理を除外する。キャッチャーの進行中トランザクションは確定/中断まで処理し、古い結果を移動先へ代入しない。中断演出は保存済み結果から手動再開する。

## 互換性・変更範囲

DB名`history-master-sample-v1`、`DB_VERSION=7`、`BACKUP_VERSION=7`、14ストア、既存キーと保存形式を維持。追加の永続フィールドやデータ移行はない。完全バックアップv1〜v6の復元互換性、v7の書き出し・検査・復元を維持する。

初正解・初習得・習得済み復習の報酬額、2連続正解の習得判定、coinClaims、回答トークン、カード、出題抽選、改行表示、キャッチャーの100枚・確率・操作・7枠配置を維持。Issue #11・#12・#14のUI変更は含めない。実データ・教材JSON・完全バックアップは登録しない。

変更ファイル：`index.html`、`tests/history_navigation_test.py`、既存4テストファイル（初期化完了待ち、版表示、管理画面リロードの期待値）、本書、`docs/SAFARI_TEST_v1.6.8.md`、`README.md`。


変更前v1.6.7：既存38件成功（75.682秒）。初回PR：全63件（既存38件＋新規25件）成功（113.381秒）。PRレビュー対応では回帰テスト5件を追加し、既存63件を維持した全68件が成功（112.826秒）。JavaScriptの`node --check`と`git diff --check`も成功。テストの削除・無効化、アプリの実行時依存追加はない。

追加した5件では、テストモードの管理画面からの選択的初期化・完全初期化・バックアップ復元後に、表示と履歴のプロフィール、リロード・bfcache相当・戻る・進む、履歴長を確認する。初期化後に同一セッションを再作成した場合と、同一セッションを含むバックアップを復元した場合も、以前の未確定選択が戻らないことを検証する。

追加テストは、反復履歴、未回答の問題・順序・選択、回答済み結果と報酬不変、次問と別時代、保存中の移動・プロフィール切替、確定直後リロード、保存失敗・実トランザクションabort、別タブの消費・同時回答・同時初回出題、残高読込失敗、初期pageshow・タブ復帰、古い非同期描画、セッション消失、キャッチャー中断・手動再開・二重確定、外部オリジン経由の履歴、バックアップ互換を検証する。

Chromium / Playwrightのlocalhost環境で架空データのみ使用。`PageTransitionEvent`と`visibilitychange`の注入はハンドラ検証であり、Safariの実bfcache・スワイプ・強制終了の確認を代替しない。実機手順は[Safari確認手順](SAFARI_TEST_v1.6.8.md)を参照。

## 制約・ロールバック

- 複数タブの即時同期は提供しない。復帰時に更新し、古い画面からの回答は保存時の照合で拒否する。別タブの編集・初期化・復元などが並行する場合は、最新状態を読み直して操作する。
- IndexedDBの耐久性・OSによるサイトデータ削除は保証できない。公開前のSafari実機確認は未実施。
- DB7のままなのでv1.6.7へコードを戻してもDBのダウングレードやデータ削除は不要。古いアプリは新しい履歴stateを扱わずホーム表示になる。全タブを閉じ、戻した版を再読み込みする。
- ロールバック前に現行v7完全バックアップを非公開に保存する。更新前バックアップを復元すると更新後の学習記録・景品が失われるため、コードのロールバックとバックアップ復元を混同しない。DB6以前への巻き戻しは今回のロールバック方法ではない。
