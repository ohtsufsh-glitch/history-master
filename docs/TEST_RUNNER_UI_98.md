# Issue #98 検証記録

2026-11-16。PR #97マージ済みのmain（0aff444、v1.7.27）から実装。
アプリ・ランナー配信識別子はv1.7.28。DB／バックアップv10、snapshot v2を維持。

## 変更と待機モード

- `index.html`：ホームを既存のhome-panel／キャッチャーの部品で統一（余白18px、見出し・料金・説明・入口）。ランナーは緑の背景・犬と旗で区別。
- `index.html`：入口から直接iframeを生成。選択欄はiframe（Canvas／操作）の下。未購入は親のbridgeがready状態だけを渡し、advance／jump／pauseは保存APIに接続しない。無料試遊を開始する経路には接続しない。
- 開始操作でプロフィール・残高・解放・実景品を確認し、studentだけ短い確認を出す。キャンセルは書込みなし。既存purchaseRunnerPlayで料金と記録を同時確定し、openRunnerSessionで正本を検証してからresumeする。購入競合は既存APIが返すactiveに接続する。
- 中断済みactiveは画面表示時にopenRunnerSessionで接続し、手動の「再開」を待つ。帰還時は既存closeで保存。記録不整合・再開不能は削除も再購入もせず表示する。
- `runner/game.js`：待機中の選択変更の再描画、終了保存後の「ゲーム開始」、対応が必要なエラーだけの表示・読み上げ通知。走行中／中断中／終了保存失敗中の選択は固定。ジャンプ・保存キュー・物理処理は既存APIのまま。
- `runner/index.html`：配信識別子と正式画面の見出し更新。
- `tests/runner_integration_test.py`：新導線へ既存統合テストを更新し、キャンセル・連打・再購入、ホームの余白、選択位置、クリア直後の解放、再開不能時の秘密保持を追加。

保存形式、トランザクション、物理、ステージ配置、能力、ハート設定、問題JSONは変更しない。Issue #94の最高点・結果画面拡充は含めない。
