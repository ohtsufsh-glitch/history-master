# Issue #93 正式画面の統合（提案）

対象はPR #96マージ後main、v1.7.26 → v1.7.27。DB v10、backup v10、snapshot v2、stageVersion 1は変更しない。物理・コース・能力は変更しない。最高点の詳細表示はIssue #94。

## 画面の境界

同一DOMへの組み込みは、既存のCSS・ID・初期化の分離が必要になる。今回は同一オリジンiframeで既存のrunner/index.htmlを使用する。親はpurchaseRunnerPlay/openRunnerSessionとIndexedDBの正本を所有し、子は描画・入力・画面ライフサイクルを担当する。外部サービス・ライブラリなし。

`embedded=1`はデモの自動初期化を抑止するだけ。親がDB照合済みセッションをonloadで一度だけ渡すまでゲームは開始不能。URLのプレイID・プロフィール・ステージ指定を権限として採用しない。親のモデルimportではCanvasが存在しないため画面を初期化しない。子の正式画面はローカルのupdateRunner/startJumpを使わず、セッションの操作だけを呼ぶ。既存の無料エンジンとの二重起動を防ぐ。

古い `/runner/` は固定コース、`/runner/?stagePreview=1` は無料デモとして維持。いずれも無料・正式成績やコインに影響しないと表示し、正式入口を学習ホームへ案内する。デモから購入・保存APIは呼ばない。未獲得の秘密キャラはデモにも表示しない。

## 利用権と購入

ホームに料金・残高・購入済み途中プレイの有無を表示する。S01のみ初期解放、S02〜S06はrunnerPlaysの前ステージ正式クリアから導出する。ロックは選択肢と説明文で理由を示す。通常4匹に加え、同じプロフィールのarcadePrizesにsecret_yunikoの実獲得があるときだけ名前と能力を公開する。復元・プロフィール変更後もDBから読み直す。

開始ボタンに30コイン（testは無料）を明示し、その操作で既存購入APIを実行する。購入トランザクションがステージ・景品所持・残高を再確認する。途中プレイがある場合はそのプレイだけを開き、新規購入しない。購入済みの再開でも、ID・game・profile・30/0コイン・startedAtと支出日時の一致、記録形式、秘密キャラの実所持をDBから照合する。

連打は画面の処理中フラグ、複数タブは既存購入トランザクションと保存時updatedAt照合で制御する。画面間競合は世代番号で古い遷移を棄却する。

## 操作と保存

セッションのjump/advanceはモデル更新前に非同期保存を待たない。JavaScriptの呼出順で同期的に更新する。ジャンプはpointerdownで反映し、キーボード/VoiceOverのclickも受け付け、ポインタ由来clickで追加ジャンプを二重実行しない。

保存は同時実行1件＋最新snapshot 1件に集約する。入力中のモデルと保存完了済みplayを分け、dirtyは最新状態と保存内容が一致したときだけ解除する。従来の2秒チェックポイント、スター・残機変更、終了時の保存条件を維持する。描画フレームは保存Promiseを待機列へ積まず、長時間フレームは既存の最大0.05秒に制限する。保存エラー時は停止して未保存を明示する。終了時は既存の原子的な結果確定を使い、コイン報酬を追加しない。

一時停止、非表示、画面回転、ページ離脱では停止・保存を試みる。復帰は必ずユーザーの再開操作を待つ。ホーム帰還は描画を止め、保存完了を待ってiframeを破棄する。OS強制終了直前の保存は保証できないため、再読み込みは最後にコミットした状態から再開する。

## 再開不能時の方針

旧snapshotやstageVersionの不一致、料金記録不整合、景品所持不明では購入済み記録を保持し、再購入ボタンには進めない。画面で理由と「バックアップを保存して保護者に確認、対応版での再開を待つ」を案内する。自動削除・自動返金・推測によるsnapshot変換はしない。DB/バックアップの仕様変更や返金は別途レビューが必要。

## 検証

実行結果は本PRのテスト記録を参照。Chromiumの代表iPhone縦横/iPad幅、タッチ、保存遅延、課金・復元・プロフィールを重点検証する。Safari実機、VoiceOver実機、文字サイズのOS設定、画面ロック・強制終了は公開前の実機確認が必要。物理・配置未変更のため48通り全攻略とUFO描画全回帰は省略する。

## PR #97 横画面レビューへの対応

正式iframeに固定min-heightを設けず、通常は85dvh、親の高さ500px以下・幅481px以上では90dvhとする。子文書の横画面CSSを実際のiframe viewportで適用する。正式画面だけ保存状況をfooterの独立行に配置し、横方向のはみ出しを防ぐ。横画面の保存状態・操作説明は余白を抑え、Canvas左・操作右を維持する。

正式画面の読み込み時と親のresize時にiframe先頭を表示し、親のヘッダーに押し下げられたボタンをスクロールで探す必要を減らす。スクロールを禁止して内容を切る方式は使わない。代表サイズでは子の文書高と内部viewport高が一致することを検証し、通常操作のスクロールは親にまとめる。文字拡大などで必要なスクロールは許容する。

同一PR内の修正のためv1.7.27は維持。課金・保存API・物理・ステージ配置の変更はない。
