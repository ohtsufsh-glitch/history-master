# Issue #113 — iPad横ランナーUI v1.7.36

PR #112マージ済みmain `df280a4`（v1.7.35）を比較基準に専用ブランチで修正。Issue #111のホームカードは対象外。

## 変更内容

- 正式画面の子viewport幅700px以上・高さ501〜900pxでは、ヘッダー、HUD、16:9 Canvas、中央ジャンプ、中央開始系の順に縦積み。ハートは従来どおりCanvas左上。
- Canvas表示幅を可用高から操作・通知等の17remを引いた高さ×16/9以内にする。論理座標・物理には触れない。ボタン幅は最大440px、縦間隔8px、タップ高48px以上。
- 3行分の保存通知をボタン下に予約し、非表示時も高さを保持。結果は既存の同一gridセルに重ねる方式を維持。文字拡大では内容の自然な伸長と必要なdocumentスクロールを許可し、隠して収めない。
- 親の横画面（幅900px以上・高さ600px以上）ではiframeを `min(85dvh, 726px)` に制限。726pxは現在の最大コンテンツ幅と操作・通知に合わせた上限。ゲーム状態によるリサイズ・postMessage・スクロール制御は追加しない。低い表示高ではCanvas側を縮小する。
- iPhone横の左右配置、iPhone縦の12px、iPad縦は既存ルールを使用。PR #103の位置維持コード、iframe方式、結果の保存確定順、料金、全キャラ/ステージ、DB/backup v10、snapshot v2は変更なし。

### 状態変化

8サイズそれぞれ開始前→走行→一時停止→再開→ゲームオーバー→再挑戦→クリア保存待ち→確定クリア→保存失敗→最後の保存から無料再開を検証。Canvasと両ボタンのx/y/幅/高さは初期値から1px以内で一致。iframeの高さも状態間で一定（測定JSONの集計）。すべて子scrollTop=0、scrollHeight=innerHeight、横オーバーフローなし。iPad横のボタン中央軸はCanvas中央から1px以内。iPhone縦はCanvas→ジャンプ12pxを維持。

保存待ちと失敗で新記録/解放を先に表示しないこと、確定クリアでS02解放、無料再開の追加課金なしも確認。文字200%では結果・通知を切り捨てずスクロールして操作へ到達可能。親へのwheelスクロールとresize後の選択欄位置維持、復帰イベントで巻き戻らないことも確認。
